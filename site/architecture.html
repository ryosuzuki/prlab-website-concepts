Keep the URLs. Change the front door.

Domain

The canonical domain is programmable-reality.org. It is already set on the lab’s public Pages repository. The old site still contains University of Calgary material. The apex has GitHub Pages DNS records, but HTTPS is not currently working correctly. This review site does not use the lab domain.

What the old names actually look like

  • People: first-last, e.g. ryo-suzuki.yaml.
  • Publication records: venue-year-first-author-surname, e.g. chi-2018-feick.yaml and uist-2020-suzuki.yaml. Extended abstracts can use a venue slug such as chi-ea. This is the documented iLab convention, not first name + last name + project title.
  • Standalone public projects already use readable slugs, e.g. /realitysketch/ and /holobots/.

Proposed structure

  • / — one vivid future scene, lab vision, and routes into research.
  • /research/ and /projects/<project-slug>/ — durable project stories, independent of venue or publication year.
  • /publications/ and /publications/<venue>-<year>-<surname>/ — bibliographic records. For new collisions, append a short project slug without renaming an existing ID.
  • /people/<first-last>/, /about/, /join/ — stable entry points.

Keep existing project sites as canonical links unless their owners choose to migrate. Map old paths to their new equivalents before cutover; on static GitHub Pages, preserve transitional URLs with static redirect pages or use a host that provides HTTP redirects.

Launch order

  1. Choose a homepage direction here. Confirm public assets, team listing, and research metadata separately from the visual direction.
  2. Build and test in the draft repo, including old URL mapping, mobile layout, keyboard navigation, metadata, and broken-link checks.
  3. Back up the production source and deployment ref. Compare the apex and www DNS against GitHub Pages’ domain guidance, and verify control of the DNS account. Check conflicting records and certificate issuance before enforcing HTTPS. Do not move the domain just to replace the site.
  4. After sign-off, deploy the chosen design to the existing lab Pages site, retaining its custom domain. Smoke-test apex, www behavior, redirects, and HTTPS; keep the backed-up deployment ref ready for rollback.
